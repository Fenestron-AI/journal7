# ROADMAP — карта разделов journal7

> Живой документ. Статус всех разделов продукта: бэкенд, фронт, контейнеризация, приоритет.
> Детальные планы разделов — в отдельных файлах: `PLAN-NORM-BAZA.md` и т.д.
> Общие статусы и решения — в `PLAN.md`.

---

## Архитектурные принципы

1. **Ядро — модульный монолит** (Kotlin, 10 модулей: core, auth, reference, contract, calculation, billing, reporting, integration, ai, app). Один процесс, одна БД, единый деплой.
2. **Отдельный контейнер — только там, где другой стек / ресурсы / темп изменений.** Сейчас это Нормативная база (Python-воркер + OCR формул + LibreOffice).
3. **Фронт — единый SPA** (React). Раздел = роут + lazy-load. Никаких micro-frontend.
4. **Инфраструктура**: PostgreSQL 16 (pgvector), Redis 7, MinIO — docker-compose.
5. **Хостинг**: один сервер, docker-compose (решение 18); образы собираются на сервере (решение 19); обновление — git pull → compose up (решение 21).

## Принципы работы с картой

- Раздел считается «рабочим», когда: API покрыт тестами, пройдены сценарии приёмочного тестирования, UI не прототип.
- Пересборка фронта — общий проект: все прототипы переезжают на целевую структуру (роуты + lazy-load, единые компоненты таблиц/форм, UX-принципы из AGENTS.md).
- Новый раздел: сначала бэкенд-контракты и тесты → потом фронт. Контейнер добавляется только при объективной причине (стек/ресурсы/команда).
